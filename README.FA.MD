# موچی دسک (Mochi Desk)

موچی دسک یک دستیار پایتونی با رابط وب محلی است. این برنامه گفت‌وگوی متنی و صوتی با Gemini، نگهداری محلی تاریخچهٔ چت و دو ابزار برای بازکردن برنامه‌های نصب‌شده یا اجرای دستورهای تأییدشدهٔ ترمینال دارد. وب‌سرور فقط روی همین رایانه و نشانی محلی `127.0.0.1` اجرا می‌شود، یک درگاه آزاد انتخاب می‌کند و صفحه را در مرورگر باز می‌کند.

[English README](README.MD)

**GitHub:** [https://github.com/m-aminiot](https://github.com/m-aminiot)

## امکانات

- **گفت‌وگوی متنی:** چند گفت‌وگو بسازید و بین آن‌ها جابه‌جا شوید. تاریخچه در فایل محلی `chats.json` ذخیره می‌شود و برای هر گفت‌وگو حداکثر ۲۰۰ نوبت نگه داشته می‌شود.
- **استریم و پیوست:** پاسخ متنی هنگام تولید نمایش داده می‌شود. تا چهار تصویر، PDF یا فایل متنی/کد پشتیبانی‌شده (هرکدام حداکثر ۸ مگابایت) پیوست کنید؛ فایل‌ها در پوشهٔ محلی `uploads/` می‌مانند و همراه پیام به Gemini فرستاده می‌شوند.
- **گفت‌وگوی صوتی:** با Gemini Live از طریق میکروفون و بلندگو صحبت کنید. زمینهٔ گفت‌وگو فقط تا پایان سشن صوتی فعال می‌ماند و به‌عنوان تاریخچهٔ عادی چت ذخیره نمی‌شود.
- **ابزارهای محلی:** از موچی بخواهید برنامه‌ای نصب‌شده را باز کند یا دستوری را در ترمینال اجرا کند. موچی پیش از اجرای هر دستور، متن دقیق آن را نشان می‌دهد و تأیید شما را می‌گیرد.
- **تنظیمات:** مدل متنی و تم رنگی را انتخاب کنید، کلید API را وارد کنید و در صورت نیاز آدرس پایهٔ سفارشی را تنظیم کنید.
- **به‌روزرسانی زنده:** رویدادهای چت و ابزار از طریق WebSocket محلی به مرورگر می‌رسند؛ هنگام اتصال مجدد، polling موقتاً جایگزین می‌شود.

## پیش‌نیازها

- پایتون نسخهٔ ۳.۱۱ یا جدیدتر.
- کلید API جمنای. واردکردن آدرس پایهٔ دلخواه اختیاری است.
- برای گفت‌وگوی صوتی، میکروفون و بلندگوی سالم و وابستگی‌های صوتی سیستم برای نصب PyAudio لازم است. چت متنی به دستگاه صوتی نیاز ندارد.

## نصب اولیه

ترمینال را باز کنید، به پوشهٔ پروژه بروید، محیط مجازی بسازید و فعال کنید، سپس کتابخانه‌ها را از فایل `requirements.txt` نصب کنید.

### مک و لینوکس

```bash
cd /path/to/Gemini
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### ویندوز PowerShell

```powershell
cd C:\path\to\Gemini
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

به‌جای مسیر نمونه، مسیر واقعی پوشهٔ پروژه را وارد کنید. اگر PowerShell اجازهٔ فعال‌کردن محیط را نداد، راهنمای Microsoft دربارهٔ Execution Policy را برای سیستم خود دنبال کنید؛ یا از Command Prompt این دستور فعال‌سازی را اجرا کنید: `.venv\Scripts\activate.bat`.

## تنظیم API

۱. از [Google AI Studio](https://aistudio.google.com/app/apikey) کلید API جمنای بسازید.
۲. موچی را طبق دستورهای بخش بعد اجرا کنید.
۳. وارد **Settings** شوید، کلید API را وارد کنید و تنظیمات را ذخیره کنید.

موچی به‌صورت پیش‌فرض مستقیم به Gemini API گوگل وصل می‌شود. اگر می‌خواهید درخواست‌ها از سرویس سازگار دیگری عبور کنند، تیک **Use a custom API base URL** را در Settings روشن کنید، آدرس پایهٔ آن سرویس را وارد کنید و تنظیمات را ذخیره کنید. با خاموش‌کردن تیک، اتصال دوباره مستقیم به Gemini API می‌رود. آدرس ذخیره‌شده با خاموش‌شدن تیک پاک نمی‌شود و بعداً می‌توانید دوباره از آن استفاده کنید. اگر کلید API وارد نشده باشد یا آدرس سفارشی فعال باشد ولی مقدار نداشته باشد، صفحهٔ آغازین شما را به Settings راهنمایی می‌کند. راه دیگر ذخیرهٔ کلید، ساختن فایل `ApiToken.txt` در پوشهٔ پروژه با این محتواست:

```text
api_key=YOUR_GEMINI_API_KEY
```

تنظیمات، کلید API، تاریخچه و ترجیحات روی همین رایانه ذخیره می‌شوند. کلیدتان را محرمانه نگه دارید؛ آن را در گیت یا تصویر صفحه منتشر نکنید.
خطاهای تشخیصی در فایل چرخشی `logs/mochi.log` نوشته می‌شوند؛ متن پیام‌های چت و کلید API عمداً در لاگ ثبت نمی‌شوند.

### پروکسی اختیاری Cloudflare Worker

فایل [`proxy/worker.js`](proxy/worker.js) یک پروکسی معکوس اختیاری برای درخواست‌های Gemini API است. این پروکسی در لایهٔ کاربرد HTTP یا لایهٔ ۷ مدل OSI کار می‌کند: درخواست HTTP را که به آدرس Worker رسیده دریافت می‌کند، hostname موجود در URL درخواست را به `generativelanguage.googleapis.com` تغییر می‌دهد و با API تابع `fetch()` در Workers درخواست تازه‌ای به گوگل می‌فرستد. این کار مقصد درخواست را عوض می‌کند؛ رکوردهای DNS یا محتوای درخواست API را بازنویسی نمی‌کند.

Worker مسیر و query string ورودی، روش HTTP، بدنه و سرآیندهای درخواست را حفظ می‌کند؛ فقط `cf-connecting-ip` و `x-real-ip` را حذف می‌کند. بنابراین مسیرهای Gemini API، نام مدل، دادهٔ درخواست و کلید APIای که موچی فرستاده، به گوگل می‌رسند. Worker کلید را تولید یا ذخیره نمی‌کند. پاسخ گوگل برای درخواست‌های معمول HTTP با سرآیندهای CORS به موچی برگردانده می‌شود. اگر هنگام ارسال درخواست به سرویس بالادستی خطای اجرایی رخ دهد، Worker پاسخ JSON با کد `502` می‌دهد؛ پاسخ‌های خطای HTTP خود گوگل با کد و بدنهٔ همان پاسخ عبور می‌کنند.

برای Gemini Live، Worker ارتقای اتصال به WebSocket را هم مدیریت می‌کند: پس از پذیرفته‌شدن اتصال از طرف گوگل، پیام‌ها را در هر دو جهت عبور می‌دهد و فریم‌های باینری صوتی را منتقل می‌کند. اگر یکی از دو سمت اتصال را ببندد یا خطا بدهد، سمت دیگر هم بسته می‌شود. این کد فقط ارتباط زنده را عبور می‌دهد و پیام‌ها یا صدا را ذخیره نمی‌کند.

تا وقتی جداگانه از URL محافظت نکنید، آدرس Worker عمومی و قابل دسترسی است. این کد احراز هویت تماس‌گیرنده یا محدودیت نرخ درخواست ندارد و سرآیندهای آزاد CORS کنترل دسترسی محسوب نمی‌شوند. هرکسی می‌تواند از URL درخواست بفرستد و از منابع Worker در حساب Cloudflare شما مصرف کند. دانستن URL به‌تنهایی کلید Gemini شما را افشا نمی‌کند، اما دیگران می‌توانند درخواست‌های خودشان را از Worker عبور دهند. پروکسی دسترسی به Google API، سهمیه، امکان پرداخت، دسترسی به مدل یا پشتیبانی منطقه‌ای ایجاد نمی‌کند. همچنین درخواست‌های `OPTIONS` را به سرویس بالادستی می‌فرستد و پاسخ preflight مرورگر را محلی تولید نمی‌کند. برای مراحل استقرار، نکات امنیتی و عیب‌یابی، [`proxy/IMPORTANT.MD`](proxy/IMPORTANT.MD) را ببینید. مستندات Cloudflare دربارهٔ API تابع [`fetch()`](https://developers.cloudflare.com/workers/runtime-apis/fetch/) و [پشتیبانی WebSocket](https://developers.cloudflare.com/workers/examples/websockets/) در Workers نیز در دسترس است.

## اجرای موچی

بعد از نصب کتابخانه‌ها، **هر بار که ترمینال جدیدی باز می‌کنید باید محیط مجازی را فعال کنید**. ابتدا وارد پوشهٔ پروژه شوید، سپس `.venv` را فعال کنید و در آخر `run.py` را اجرا کنید.

### مک و لینوکس — در هر بار اجرا

```bash
cd /path/to/Gemini
source .venv/bin/activate
python run.py
```

### ویندوز PowerShell — در هر بار اجرا

```powershell
cd C:\path\to\Gemini
.venv\Scripts\Activate.ps1
python run.py
```

تا وقتی از موچی استفاده می‌کنید ترمینال را باز نگه دارید. برای متوقف‌کردن سرور، در همان ترمینال `Ctrl+C` بزنید. در اجرای بعدی، ترمینال جدید باز کنید و سه مرحلهٔ بالا را دوباره انجام دهید. لازم نیست محیط را دوباره بسازید یا کتابخانه‌ها را دوباره نصب کنید، مگر اینکه پوشهٔ `.venv` پاک شده باشد یا وابستگی‌ها تغییر کرده باشند.

## نکته‌های نصب صدا

PyAudio از کتابخانهٔ سیستمی PortAudio استفاده می‌کند. بسته به سیستم‌عامل، نسخهٔ پایتون و معماری پردازنده، ممکن است pip مجبور شود PyAudio را کامپایل کند. برای نمونه، در فدورا ممکن است بسته‌های زیر لازم باشند:

```bash
sudo dnf install gcc python3-devel portaudio-devel
```

نام بسته‌ها در توزیع‌های لینوکس متفاوت است. اگر نصب خطا داد، متن کامل خطا و راهنمای سیستم‌عاملتان را برای یافتن کامپایلر، سرآیندهای توسعهٔ پایتون یا PortAudio بررسی کنید. برای گفت‌وگوی صوتی، سیستم‌عامل نیز باید اجازهٔ دسترسی به میکروفون را به برنامه بدهد.

## ابزارهای داخلی

### بازکردن برنامه

ابزار `open_app` از سیستم‌عامل می‌خواهد برنامه‌ای نصب‌شده را با نام باز کند. برنامه باید نصب باشد و از طریق فهرست برنامه‌ها، لانچر، Start Menu یا مسیر اجرایی قابل پیدا کردن باشد. موفقیت ابزار یعنی سیستم‌عامل درخواست اجرا را پذیرفته است؛ این موضوع رفتار بعدی برنامه را گزارش نمی‌کند.

### اجرای دستور ترمینال

ابزار `run_terminal_command` دستور را از پوشهٔ پروژه اجرا می‌کند، خروجی را می‌گیرد و پس از ۴۵ ثانیه متوقف می‌شود. رابط محلی متن دقیق دستور را نشان می‌دهد و پیش از اجرا تأیید شما را می‌گیرد. می‌توانید دستور در حال اجرا را از رابط لغو کنید.

این ابزار یک اجراکنندهٔ دستور غیرتعاملی است و نشست معمولی ترمینال باز نمی‌کند. دستورهایی که منتظر ورودی صفحه‌کلید می‌مانند—از جمله بسیاری از درخواست‌های رمز `sudo`، نشست تعاملی SSH و ویرایشگرهای متنی—ممکن است خطا بدهند یا متوقف شوند. دستورهای تعاملی یا دارای دسترسی ویژه را خودتان در ترمینالی که کنترلش را دارید اجرا کنید و فقط دستورهایی را تأیید کنید که از کارشان مطمئن هستید.

## مدل‌ها

مدل متنی را از منوی چت انتخاب کنید. گزینه‌های فعلی عبارت‌اند از `gemini-3.5-flash-lite`، `gemini-3-flash-preview` و `gemini-2.5-flash-lite`. گفت‌وگوی صوتی از `gemini-3.8-live` استفاده می‌کند. دسترسی به مدل‌ها به سرویس API، حساب و کلید شما بستگی دارد.

## داده‌ها و حریم خصوصی

هنگام اجرای سورس، گفت‌وگوهای متنی در فایل `chats.json` داخل پوشهٔ پروژه ذخیره می‌شوند. موچی سرویس میزبانی تاریخچهٔ چت ندارد، اما برای پاسخ‌دادن، زمینهٔ گفت‌وگوی انتخاب‌شده را به سرویس Gemini-compatible که تنظیم کرده‌اید می‌فرستد. فایل‌های محلی رمزگذاری نمی‌شوند؛ افرادی که به حساب سیستم یا فایل‌های پروژه دسترسی دارند ممکن است بتوانند آن‌ها را بخوانند.

صدای گفت‌وگوی زنده هنگام سشن فعال به سرویس Gemini Live تنظیم‌شده فرستاده می‌شود. زمینهٔ صوتی فقط برای همان سشن نگه داشته می‌شود و به‌عنوان تاریخچهٔ عادی ذخیره نمی‌شود. وب‌سرور محلی روی `127.0.0.1` و HTTP اجرا می‌شود و یک درگاه محلی انتخاب می‌کند؛ برنامه برای استفاده روی همان رایانه طراحی شده است، نه میزبانی در شبکه.

فایل `soul` شخصیت و دستورالعمل‌های رفتاری موچی را نگه می‌دارد. ویرایش یا حذف آن می‌تواند رفتار دستیار را تغییر دهد.

## عیب‌یابی

- **پیام تنظیمات می‌بینید:** در Settings هم کلید API و هم آدرس پایهٔ API را وارد کنید.
- **خطای `ModuleNotFoundError`:** مطمئن شوید در پوشهٔ پروژه هستید و محیط `.venv` در همین ترمینال فعال است؛ سپس وابستگی‌ها را با `python -m pip install -r requirements.txt` نصب کنید.
- **نصب PyAudio خطا می‌دهد:** بسته‌های سیستمی صدا و کامپایلر موردنیاز سیستم‌عاملتان را نصب کنید و نصب pip را دوباره انجام دهید.
- **درخواست API یا مدل خطا می‌دهد:** کلید، آدرس پایهٔ API، دسترسی کلید به مدل انتخاب‌شده و سهمیه یا وضعیت سرویس را بررسی کنید.
